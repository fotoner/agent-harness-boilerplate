# handoff

세션 컨텍스트 저장 + 핸드오프 메타프롬프트 생성 + 클립보드 복사를 한 번에 수행한다.

## 핵심 원칙

1. **자기완결 메타프롬프트**: 다음 세션이 이 텍스트 하나만 붙여넣어도 착수할 수 있어야 한다. 체크포인트 경로, 레포/브랜치 상태, 잔여 작업, 첫 액션을 모두 담는다.
2. **미커밋·미푸시 상태는 반드시 명시**: 커밋 이월이 다음 세션의 브랜치 오염으로 이어지는 것을 방어한다. "없음"도 명시한다.
3. **민감정보 금지**: 메타프롬프트에 토큰·키·개인정보를 넣지 않는다.

## 절차 (체크리스트)

0. **작업일지 선행 확인**
   - 이번 세션에 기록 가치 있는 작업(파일 변경·결정)이 있는데 `docs/work-log/` 아래에 작업일지가 아직 없으면, 핸드오프 전에 `work-log` 작성을 먼저 제안한다 (작성 후 이 절차를 계속). 핸드오프는 세션의 마지막 행동이다.

1. **컨텍스트 저장**
   - 컨텍스트 저장 메커니즘이 있으면 호출한다. 보일러플레이트가 gstack 기반이면 Skill 도구로 `context-save` 를 호출한다 (사용자가 준 저장 관점 인수를 그대로 전달). gstack 이 없으면 잔여 컨텍스트를 메타프롬프트 본문에 직접 담는 것으로 갈음한다.
   - 저장 후 체크포인트 경로를 확인한다.

2. **세션 상태 수집**
   - 현재 브랜치, 미커밋 변경(`git status --porcelain`), 미푸시 커밋(`git log @{u}..` 또는 upstream 부재)을 확인한다.

3. **메타프롬프트 생성** — 고정 템플릿:

   ```markdown
   # 세션 핸드오프 — <한 줄 요약>

   ## 현재 상태
   - 브랜치: <branch>
   - 미커밋: <없음 | 파일 N개 — 핵심 경로> / 미푸시: <없음 | 커밋 N개>
   - 체크포인트: <경로 또는 "없음 — 본문에 컨텍스트 인라인">

   ## 잔여 작업 (우선순위)
   1. <가장 먼저 할 일 — 완료 기준 포함>
   2. ...

   ## 다음 세션 첫 액션
   <컨텍스트 복원 지시 (예: /context-restore <경로 또는 #번호>)>
   <복원 직후 수행할 1-2개 지시>
   ```

4. **클립보드 복사**
   - 메타프롬프트를 `pbcopy` 로 복사한다 (Bash, heredoc 사용; 리눅스면 `xclip`/`wl-copy`).
   - 복사가 실패하면(샌드박스 등) 메타프롬프트를 코드블록으로 출력하고 수동 복사를 안내한다.

5. **보고**
   - 체크포인트 경로 + 복사 성공 여부 + 미커밋/미푸시 요약을 1-2줄로 보고하고 멈춘다.

## 자주 하는 실수

| 실수 | 교정 |
|------|------|
| 저장만 하고 메타프롬프트 생성을 잊음 | 이 스킬은 둘이 한 단위다. |
| 미커밋 상태를 빠뜨림 | 현재 상태 섹션은 생략 불가. "없음"도 명시. |
| "자세한 내용은 체크포인트 참고"식 본문 | 잔여 작업과 첫 액션은 메타프롬프트 본문에 직접. |
| 복사 실패를 침묵 | 실패 시 코드블록 출력 + 수동 복사 안내. |

## Red Flags

- 메타프롬프트에 체크포인트 경로(또는 인라인 컨텍스트)가 없다.
- 다음 세션 첫 액션이 비어 있거나 막연하다 ("이어서 작업").
- 메타프롬프트 생성 후 다른 새 작업을 시작하려 한다 — 핸드오프는 세션의 마지막 행동이다.
