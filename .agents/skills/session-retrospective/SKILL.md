# session-retrospective

현재 세션에서 발생한 실수를 모아 회고하고, **재발 방지 규칙**을 CLAUDE.md /
QUALITY_RULES.md 등 적절한 파일에 추가하도록 "제의"한다. 회고 결과는
`docs/mistake/` 에 영구 기록되고, 다음 회고 실행 시 그 기록을 참조해 반복
패턴을 자동 식별한다. **점진적 하네스(Progressive Harness)** 원칙을 자동화한 스킬이다.

## 적용 범위

- 이 스킬은 세션 회고 + 규칙 제안 + 실수 기록 + 패턴 식별에 사용한다.
- 코드 디버깅은 `investigate` 등 디버깅 스킬.
- 작업일지 기록은 `work-log` / `work-log-daily` 스킬.
- 스프린트 차원 회고는 `manage-cycle` 스킬.

## 핵심 원칙

1. **사용자 승인 없이 어떤 규칙 파일도 수정하지 않는다.** 이 스킬의 출력은 본질적으로 "제안서"다.
   - CLAUDE.md, QUALITY_RULES.md 등 어떤 규칙 파일도 직접 Edit/Write 하지 않는다.
   - 사용자가 "적용해줘" / "추가해줘" / "OK" 등 명시적으로 동의한 항목만 반영.
   - 동의 범위가 모호하면 다시 확인. "전부 적용해줘"가 아니면 항목별로 확인.
   - **예외**: `docs/mistake/` 의 기록 파일 / INDEX.md 는 본 스킬이 관리하는 자기 영역이라 매 실행 시 추가/갱신한다 (사용자 별도 승인 불필요).
2. **수집 → 과거 참조 → 분류 → 라우팅 → 제안 → (승인 후) 반영 → 기록**. 절차를 건너뛰지 않는다.
3. **이미 있는 규칙은 보강하고, 새 규칙은 최소한으로 추가한다.** 중복 규칙을 만들지 않는다.
4. **"왜 추가했는지"를 기록한다.** 점진적 하네스 원칙에 따라 신규/보강 규칙에 트리거가 된 실수 요지를 1줄로 인라인 메모(`(트리거: ...)`).
5. **반복 패턴은 자동 격상한다.** 같은 패턴 태그가 `docs/mistake/` 에 N회 이상 누적되면 분류를 격상하거나 린터/훅 승격을 제안한다.

## 무엇을 "실수"로 간주하는가

다음 신호 중 하나라도 해당되면 회고 대상에 포함:

| 카테고리 | 신호 예시 |
|---------|----------|
| **사용자 정정** | "아니야", "그게 아니라", "잘못됐어", "다시", "방향이 틀렸어" |
| **검증 누락** | 코드/설정을 안 읽고 추측으로 답함, 사용자가 직접 확인해서 정정 |
| **가정 빗나감** | 의도 파악 실패, 기본 플로우 vs 사용자 의도 충돌 |
| **규칙 위반** | 기존 CLAUDE.md/QUALITY_RULES/Memory 규칙을 어김 |
| **반복 실수** | 같은 세션 내 같은 종류 실수 2회 이상 |
| **불필요한 작업** | 요청 외 변경, 자동 수정, 광범위한 staging |
| **승인 없는 destructive 동작** | reset/checkout/force-push/stash 등을 임의로 수행 또는 시도 |
| **명시적 사용자 피드백** | "다음부턴 이렇게 해", "이거 룰에 추가해" |

### 실수가 아닌 것

- **사용자가 명시적으로 override 한 동작**: 규칙을 우회하라고 지시한 경우는 실수가 아니다.
- **단순 typo / 한 번 고친 표현**: 패턴이 아니면 규칙 대상 아님.
- **사용자 취향 차이**: 객관적 오류가 아니라 선호 변경은 기존 규칙 보강으로만 처리.

## 기록 디렉토리 (`docs/mistake/`)

```
docs/mistake/
├── README.md           # 디렉토리 의도와 형식 안내
├── INDEX.md            # 모든 회고의 실수 1줄 요약 + 패턴 태그 + 누적 카운터
└── YYYY/
    └── MM/
        └── YYYY-MM-DD - <session-slug>.md
```

- 프로젝트 루트 기준 상대 경로. 연도 4자리, 월 0-padding 2자리.
- `session-slug` 는 회고 대상 세션의 작업 키워드. 같은 날짜·slug 가 있으면 `-2`, `-3` 인덱스. **덮어쓰지 않는다.**

### 회고 파일 포맷 (frontmatter + 본문)

```markdown
---
date: 2026-05-27
session_slug: auth-flow-cleanup
mistakes:
  - id: M-2026-05-27-1
    title: <짧은 요약>
    category: A | B | C | D
    pattern_tags: [verification-skip-pre-answer]
    rule_links:
      - docs/QUALITY_RULES.md#커밋-메시지-self-contained-원칙
applied_rules:
  - file: docs/QUALITY_RULES.md
    section: 커밋 메시지 self-contained 원칙
    kind: new
deferred_proposals: []
---

# 세션 회고 — 2026-05-27 auth-flow-cleanup

## M-2026-05-27-1: <제목>

- **무슨 일**: <사실 1–2문장>
- **정정**: <사용자가 어떻게 정정했는지>
- **분류**: B (기존 규칙 적용 실패)
- **패턴 태그**: `verification-skip-pre-answer`
- **관련 규칙**: `docs/QUALITY_RULES.md` "..."

## 적용된 규칙

- (승인되어 반영한 규칙 변경 목록)

## 보류된 제안

(사용자가 보류한 항목. 다음 회고에서 같은 패턴 재발 시 재제안 후보.)
```

### INDEX.md 포맷

```markdown
# Mistake Index

본 디렉토리의 모든 회고에서 식별된 실수의 1줄 요약 + 패턴 태그 + 누적 카운터.
스킬은 회고 시작 시 이 파일을 참조해 반복 패턴을 식별한다.

## 패턴 태그별 누적

| 패턴 태그 | 누적 횟수 | 마지막 발생 | 활성 규칙 |
|----------|----------|------------|----------|
| verification-skip-pre-answer | 1 | 2026-05-27 | docs/QUALITY_RULES.md#검증-우선 |

## 회고 목록

- [2026-05-27] auth-flow-cleanup → 3 mistakes (B×2, A×1) — `docs/mistake/2026/05/2026-05-27 - auth-flow-cleanup.md`
```

### 패턴 태그 사전 (kebab-case)

자주 등장하는 패턴은 다음 태그로 통일한다. 새 패턴은 자유 생성하되 기존과 중복되지 않게.

- `verification-skip-pre-answer` — 추측으로 답하고 사용자가 직접 확인
- `unauthorized-destructive-action` — reset / force-push / stash 임의 수행
- `subagent-prompt-trust` — implementer prompt 한 줄에만 의존, dispatcher 검증 누락
- `scope-creep` — 요청 외 변경 추가
- `assumption-mismatch` — 사용자 의도 vs 기본 플로우 충돌
- `repeat-correction` — 같은 세션 내 같은 정정 2회 이상
- `bulk-rewrite-verification-skip` — sed / 일괄 변환 후 검증 미흡
- `commit-metadata-leak` — 휘발성 플랜 라벨이 commit / 주석 / 브랜치명에 박힘

(태그는 프로젝트마다 늘어난다 — 처음엔 비어 있을 수 있다.)

## 라우팅 (어느 파일에 제안할지)

| 규칙 성격 | 추천 파일 |
|----------|-----------|
| 전반적 작업/협업 철학·에이전트 규율 | `CLAUDE.md` |
| 코드 품질, TDD, 검증 등 품질 규칙 | `docs/QUALITY_RULES.md` |
| 커밋/PR/브랜치/EARS 작업 형식 등 컨벤션 | `docs/CONVENTIONS.md` |
| 코드 리뷰 절차 | `docs/CODE_REVIEW.md` |
| 에러 처리/재시도 등 신뢰성 | `docs/RELIABILITY.md` |
| 시크릿/의존성/보안 | `docs/SECURITY.md` |
| 모든 프로젝트 공통 개인 선호 | `~/.claude/CLAUDE.md` (전역) |

### 라우팅 기본값과 예외

- **기본**: 프로젝트 차원 작업/협업 규칙 → 프로젝트 `CLAUDE.md`.
- **예외**: 품질/검증 절차 위반 → `docs/QUALITY_RULES.md`; 커밋/PR/브랜치 컨벤션 위반 → `docs/CONVENTIONS.md`.
- **글로벌 제안은 보수적으로**: 사용자가 명시적으로 "전역에 넣어줘"라고 하지 않는 한 `~/.claude/CLAUDE.md` 는 제안하지 않는다.

## 절차 (체크리스트)

### 0. 과거 기록 참조 (Reference Past)

- `docs/mistake/INDEX.md` 를 Read. 패턴 태그별 누적 횟수와 활성 규칙 위치를 머리에 새긴다.
- 최근 3~5 개 회고 파일을 빠르게 훑어 본 세션 실수와 유사한 패턴이 있는지 확인.
- 여기서 식별한 "이전에도 비슷한 패턴 있었는가" 정보는 분류 단계의 격상 기준이 된다.

### 1. 수집 (Collect)

- 세션 대화를 처음부터 훑어 위의 "실수" 신호를 모두 찾는다.
- 각 실수에 대해: **무슨 일(사실)**, **사용자가 어떻게 정정했는지**, **패턴 태그**(기존 사전 우선, 없으면 신규 kebab-case)를 메모.
- 사실은 verbatim 가깝게 보존. 임의 해석 금지.

### 2. 분류 (Classify)

| 분류 | 의미 |
|------|------|
| **A. 일회성** | 패턴 아님. 규칙화 불필요. 기록만 한다. |
| **B. 기존 규칙 적용 실패** | 이미 규칙이 있는데 못 지킴. 규칙 추가 X, 자기반성만. |
| **C. 기존 규칙 보강 필요** | 비슷한 규칙은 있지만 이번 경우를 명시적으로 다루지 않음. 기존 항목 수정 제안. |
| **D. 신규 규칙 필요** | 관련 규칙이 전혀 없음. 새 항목 추가 제안. |

#### 반복 패턴 자동 격상

INDEX.md 의 누적 횟수가 다음에 해당하면 분류를 격상한다.

- **같은 패턴 태그 누적 2회 이상 + 활성 규칙 없음** → A → D (신규 규칙 제안).
- **같은 패턴 태그 누적 2회 이상 + 활성 규칙 있음** → B → C (기존 규칙 보강 — 케이스 명시 부족).
- **같은 패턴 태그 누적 3회 이상 + 활성 규칙 있음** → C → "린터/훅 승격 후보" (`docs/QUALITY_RULES.md` "점진적 하네스" 2번 trigger).

C/D 만 제안 대상이다. **A는 기록만, B는 자기반성만.**

### 3. 라우팅 검토 (Route)

C/D 각 항목에 대해 위 라우팅 표로 추천 파일을 결정한다.

**중요**: 실제로 추천 파일을 **Read** 해서 (1) 비슷한 항목이 이미 있는지(있으면 C 로 재분류), (2) 끼워 넣을 섹션, (3) 파일의 톤/포맷을 확인한다.

### 4. 제안서 작성 (Propose)

다음 형식으로 사용자에게 제시한다. **이 시점에 어떤 규칙 파일도 수정하지 않는다.**

```markdown
## 세션 회고

### 과거 패턴 참조 (있을 때만)
- `<태그>` 누적 N회, 활성 규칙 `<경로>` 존재. 이번이 (N+1)회 — "린터/훅 승격" 검토 필요.

### 식별된 실수
1. **<실수 한 줄 요약>**
   - 무슨 일 / 정정 / 패턴 태그 / 분류 (격상 사유 있으면 명시)

### 제안 — 보강 (C) / 신규 (D)
**[1] <간단 제목>**
- 대상 파일 / 위치 / 추가안·보강안(코드블록) / 이유("이번 세션에서 …" + 해당 시 "누적 N회")

### 자기반성 (B)
- **<실수 요약>** — 이미 `<파일>:<섹션>`에 규칙 있음. 다음 세션에서 더 잘 지킬 것.

### 승인 요청
적용할 항목 선택: 전체 / [1]만 / [2]만 / 수정해서 적용 / 모두 보류
```

### 5. 승인 후 반영 (Apply, 승인 후에만)

- 사용자가 명시적으로 동의한 항목만 Edit 으로 반영.
- 추가하는 규칙에는 **이번 실수 요지 1줄을 `(트리거: ...)` 인라인 메모**로 포함.
- 반영 후 어떤 파일이 어떻게 바뀌었는지 1–2줄로 보고.
- 동의되지 않은 제안은 본 세션 기록 파일의 `deferred_proposals` 에만 기록. 다른 파일에 옮기지 않는다.

### 6. 기록 저장 (Persist)

- 본 세션 회고를 `docs/mistake/YYYY/MM/YYYY-MM-DD - <session-slug>.md` 로 저장 (같은 날짜·slug 면 `-2` 인덱스, 디렉토리 없으면 `mkdir -p`).
- `docs/mistake/INDEX.md` 갱신: "패턴 태그별 누적" 표에 이번 태그 각각 +1(신규면 행 추가, 마지막 발생 갱신), "회고 목록"에 한 줄 추가.
- 기록은 **사용자 별도 승인 없이** 저장한다 (본 스킬의 자기 영역).

### 7. 보고

- 적용한 항목 / 보류한 항목 / 자기반성 항목 / 저장된 기록 경로를 한 화면으로 요약하고 끝.

## 제안서 작성 시 주의

- **사실 보존**: 사용자의 정정 표현은 가능한 한 verbatim 인용. 임의 paraphrase 금지.
- **검증 가능한 추천**: "비슷한 규칙이 이미 있다"고 말하기 전에 실제 파일을 Read 로 확인.
- **간결성**: 한 실수에 한 제안. 한 제안에 여러 항목을 묶지 않는다.
- **타협 가능성**: 사용자가 "그건 너무 강해" / "이렇게 바꿔"라고 하면 그 자리에서 수정안 재작성.
- **승인 표현 해석**: "OK"/"전부 적용" → 모두 / "[2]만" → 해당 항목만 / "보류"/"다음에" → 적용 안 함(단 `deferred_proposals` 기록은 됨) / 모호하면 다시 묻는다.

## 자주 하는 실수

| 실수 | 교정 |
|------|------|
| 승인 없이 CLAUDE.md 를 바로 수정 | 제안서 단계에서 멈춘다. 명시적 동의 후에만 Edit. |
| 일회성 실수까지 규칙화 제안 | 분류 A 는 기록만. 단 INDEX.md 누적으로 격상 가능. |
| 기존 규칙 확인 없이 신규로 분류 | 추천 파일을 실제로 Read 해서 유사 항목 검색. |
| 라우팅을 단일 파일(CLAUDE.md)로만 추천 | 성격에 따라 docs/QUALITY_RULES, docs/CONVENTIONS 등 분기. |
| 프로젝트 규칙으로 충분한데 글로벌을 건드림 | 글로벌은 명시 지시 없으면 손대지 않는다. |
| 사용자 override 를 실수로 분류 | 명시적으로 다른 방향을 지시한 동작은 회고 대상 아님. |
| 트리거 메모 없이 규칙만 추가 | 새 규칙엔 "이번 실수 요지 1줄" 인라인 포함. |
| `docs/mistake/` 기록 저장 누락 | 6단계는 사용자 별도 승인 없이 항상 실행. |
| INDEX.md 참조 없이 분류 결정 | 0단계 누락 — 반복 패턴 격상 기회 놓침. |

## Red Flags

- 사용자 승인 없이 **규칙 파일**을 Edit/Write 하려고 한다.
- 분류 A (일회성)인데 규칙 제안을 만들고 있다 (격상 조건 충족 시 예외).
- 추천 파일의 기존 내용을 Read 없이 "비슷한 항목 없음"이라고 단정한다.
- 사용자가 명시적으로 override 한 동작을 "실수"로 회고 대상에 넣고 있다.
- 보류된 제안을 사용자 동의 없이 다른 파일에 옮겨 적으려 한다.
- 새 규칙에 트리거 메모가 빠져 있다.
- 글로벌 `~/.claude/CLAUDE.md` 를 사용자 명시 지시 없이 수정 대상에 넣었다.
- `docs/mistake/` 디렉토리/INDEX.md 참조를 건너뛰고 분류 단계로 직행했다.
- 회고 종료 시점에 `docs/mistake/` 기록이 저장되지 않았다.
