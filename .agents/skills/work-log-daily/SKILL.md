# work-log-daily

`docs/work-log/YYYY/MM/` 에 저장된 **금일 work-log 문서들**을 읽어 종합 요약을 `docs/work-log/daily/YYYY-MM-DD.md` 로 저장한다.

## 적용 범위

- 이 스킬은 일별 종합 요약 문서 생성에 사용한다.
- 개별 세션 작업일지 작성은 `work-log` 스킬을 사용한다.
- 스프린트 차원의 회고는 `manage-cycle` 스킬을 사용한다.

## 핵심 원칙

1. **자기완결성 (Self-Contained)**: daily 문서 한 장만 읽어도 그날 무슨 일이 있었는지 이해할 수 있어야 한다.
   - 개별 work-log 파일을 **링크하거나 참조하지 않는다**. "자세한 내용은 `X.md` 참고" 금지.
   - 필요한 사실(파일 경로, 결정, 검증 결과)은 본문에 직접 옮겨 적는다.
2. **종합 (Synthesis), 복사 아님**: 개별 work-log 본문을 그대로 붙이지 않는다. 핵심을 압축한 요약과 불릿으로 재구성한다.
3. **사실 위주 + 출처 보존**: 각 작업 항목에 원본 work-log 파일명을 메타데이터로 표기한다 (`출처: 2026-05-27 - 작업이름.md`). 이는 외부 링크가 아니라 추적용 식별자다.
4. **단일 권한 원천**: daily 문서는 work-log 에서 파생된 것이다. 충돌하면 work-log 가 진실. daily 재생성 시 work-log 를 다시 읽는다.

## 파일 경로 규칙

```
docs/work-log/
├── YYYY/MM/                       # 개별 work-log (work-log 스킬이 생성)
│   └── YYYY-MM-DD - 작업이름.md
└── daily/                         # 일별 종합 요약 (이 스킬이 생성)
    └── YYYY-MM-DD.md
```

- 프로젝트 루트 기준 상대 경로. daily 디렉토리는 평면 구조(년/월 분리 없음).
- 파일명: `YYYY-MM-DD.md`. 날짜는 세션 시작 시점의 현재 날짜(`currentDate` 또는 `date +%F`).
- 중복 시 인덱스(`-2`, `-3` …). 사용자가 명시적으로 "덮어써줘"라고 지시한 경우에만 덮어쓰기.

## 입력 수집 절차

1. **날짜 결정**: `currentDate` 또는 `date +%F`.
2. **년/월 경로 계산**: `docs/work-log/YYYY/MM/`.
3. **금일 파일 글로빙**: 해당 디렉토리에서 `YYYY-MM-DD*.md` 패턴 매칭 (다른 날짜 파일 제외).
4. **각 파일 읽기**: Read 도구로 본문 전체를 읽는다.
5. **파일이 0개이면 중단**: 사용자에게 "오늘 작성된 work-log 가 없음. 먼저 `work-log` 스킬로 작업일지를 작성해야 함."이라고 보고하고 종료.

```bash
DATE=$(date +%F); YEAR=${DATE:0:4}; MONTH=${DATE:5:2}
ls "docs/work-log/$YEAR/$MONTH/$DATE"*.md 2>/dev/null
```

## 문서 포맷

daily 문서는 정확히 다음 4개 섹션을 가진다. **순서 고정, 제목 고정.**

```markdown
# YYYY-MM-DD daily

## 하루 요약

3–6문장. 오늘 무엇을 했고 / 어떤 흐름이었으며 / 전체적으로 어떻게 마무리됐는지.
개별 work-log 파일 링크/참조 금지.

## 작업 목록

오늘 수행한 작업을 work-log 단위로 불릿 정리. 각 항목:

- **작업이름** — 1–2문장 요약. 핵심 결정과 결과 포함.
  - 변경: 주요 파일/모듈 (프로젝트 루트 기준 경로)
  - 검증: 무엇을 확인했는지 (없으면 "미검증" 명시)
  - 출처: `2026-05-27 - 작업이름.md`

## 미완료 / 다음 작업

각 work-log 의 "내용"·"기존 계획과의 차이"에서 보류/TODO/막힌 부분을 모은다.
모두 완료됐다면 "모든 작업 완료. 미해결 항목 없음."이라고 명시.

## 메모

하루 전반의 관찰/배움/주의사항. 해당 없으면 "특이사항 없음."이라고 적는다.
```

- **"하루 요약"**: 개별 작업 나열이 아니라 하루의 narrative.
- **출처 라벨**: 파일 식별자이지 링크가 아니다. 마크다운 링크 문법 사용 금지.
- **사실/추측 분리**: 개별 work-log 에 "미검증"으로 표시된 항목은 daily 에도 그대로 "미검증" 표기.

## 절차 (체크리스트)

1. **날짜 결정 + 경로 계산** — `docs/work-log/YYYY/MM/` 입력, `docs/work-log/daily/YYYY-MM-DD.md` 출력.
2. **금일 work-log 수집** — 글로빙 → 모두 Read. 0개면 보고하고 종료.
3. **종합 작성** — 각 work-log 의 핵심 사실 추출. "하루 요약"은 가로지르는 narrative, "작업 목록"은 work-log 당 1개 불릿, "미완료"는 TODO/보류 통합, "메모"는 하루 전반의 관찰.
4. **중복 검사 및 저장** — 동일 경로면 인덱스. 디렉토리 없으면 `mkdir -p`. Write 로 저장.
5. **보고** — 저장 경로 + 종합한 work-log 개수를 1–2줄로 보고.

## 자주 하는 실수

| 실수 | 교정 |
|------|------|
| 개별 work-log 본문을 그대로 복사 | 핵심만 압축. 종합이지 모음집이 아님. |
| "자세한 내용은 `X.md` 참고" 식 외부 참조 | 사실을 daily 본문에 직접 옮긴다. `출처:` 라벨은 식별자 용도로만. |
| 다른 날짜 work-log 를 포함 | 글로빙 패턴은 **오늘 날짜로 시작하는** 파일만. |
| 같은 파일명을 그냥 덮어씀 | 인덱스를 붙여 새 파일 생성 (사용자 명시 지시 예외). |
| "하루 요약"이 작업 목록의 첫 줄 복붙 | 요약은 가로지르는 narrative. |
| 0개 work-log 일 때 빈 daily 생성 | work-log 먼저 작성하라고 알리고 종료. |

## Red Flags

- 본문에 `참고:`, `자세한 내용은`, `[…](…)` 같은 외부 문서 링크가 있다.
- "작업 목록"에 오늘 날짜가 아닌 work-log 가 섞여 있다.
- "하루 요약"이 단순히 작업명을 나열하고 있다.
- 같은 daily 파일명을 덮어쓰려고 한다 (사용자 명시 지시 없는 경우).
- "메모" 섹션이 통째로 빠졌다.
- 0개 work-log 인데 빈 daily 문서를 작성하려 한다.
